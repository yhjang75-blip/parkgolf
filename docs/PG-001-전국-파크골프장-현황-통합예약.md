## 1. 문제

- 사용자는 파크골프를 직접 치는 이용자다.
- 전국 파크골프장의 **위치와 현황(코스 규모, 운영 상태, 이용료 등)**을 한곳에서 확인하기 어렵다.
- 파크골프장 대부분을 지자체나 시설관리공단이 운영하며, **지자체마다 예약 사이트가 따로 있어** 여러 곳을 돌아다니며 예약해야 한다.
- 그래서 **현황 조회와 예약을 하나의 사이트에서** 처리하고 싶다.

확인된 근거: 사용자 진술 (사용자가 직접 겪은 불편)
아직 확인하지 않은 사실: 전국 파크골프장 수, 공공데이터 제공 여부, 지자체별 예약 시스템 종류와 예약 페이지 주소

## 2. 목표 산출

**Python으로 만드는 웹 애플리케이션 1개.** 가장 현실적인 방법부터 단계별로 만든다.

| 단계 | 내용 | 상태 |
|---|---|---|
| **1차 (이번 범위)** | ① 전국 현황: **처음부터 전국** 파크골프장 목록과 지도 표시, 시·도 / 시·군·구별 검색과 필터, 장별 상세 정보 | 확정 |
| | 상세 정보 필수 항목 (사용자 지정): **홀 수, 위치 정보(주소·지도 좌표·길찾기), 필드 상태** | 확정 |
| | 필드 상태 세부 항목 (사용자 지정): **운영·휴장 여부, 날씨, 잔디 상태, 코스 난이도** | 확정 |
| | 상세 정보 기본 항목: 운영시간, 이용료, 운영 주체, 연락처, 예약 방법 | 확정 |
| | ② 예약 연결 (Q1-A): 구장마다 **공식 예약 페이지로 바로 이동**하는 버튼. 온라인 예약이 없는 구장은 전화번호와 현장 접수 안내 | 확정 |
| 2차 (인지도가 늘면) | 이용자가 잔디 상태·코스 난이도를 직접 평가하는 기능 (장난 글 방지 장치 포함) | 방향 확정. 시작 시점은 이용 현황을 보고 결정 |
| 이후 (장기 목표) | 빈 시간대 조회 (B), 지자체 협약을 통한 사이트 안 예약 (C) | 보류. 1차 완료 뒤 다시 결정 |

산출물 위치(예정): 현재 작업 폴더 `바이브코딩-01/`

## 3. 대상

- **사용자**: **파크골프 이용자 전체** (사용자 확정, Q2). 요청자 본인만 쓰는 도구가 아니다.
- 중장년·고령층 비율이 높을 것으로 **예상**한다 (가정이며 확인 필요) → 큰 글씨와 단순한 화면이 필요할 수 있음
- **사용 기기**: **PC 중심으로 쓰고, 스마트폰에서도 같은 서비스를 쓸 수 있어야 한다** (사용자 확정, Q3).
- **사용 맥락**: 가까운 구장이나 여행지 근처 구장을 찾고, 홀 수와 필드 상태를 확인한 뒤 공식 예약 페이지로 넘어가 예약한다. 현장에 갈 때는 스마트폰으로 위치와 길찾기를 본다.

## 4. 제약

**기술**
- 개발 언어: **Python** (사용자 지정)
- 웹 프레임워크, DB, 지도 API(카카오맵 / 네이버지도 등)는 아직 정하지 않음 → 설계 단계에서 정한다.

**데이터 (가정, 확인 필요)**
- 구장 현황 데이터는 공공데이터포털, 대한파크골프협회, 각 지자체 공개 자료에서 모을 수 있을 것으로 **가정**한다.
- 데이터 출처, 갱신 주기, 이용 허락 조건(라이선스)을 확인해야 한다.
- 구장별 **공식 예약 페이지 주소**는 한곳에 모인 자료가 없을 수 있다. 직접 조사해 목록을 만들어야 할 수 있다 (가정).
- 예약 페이지 주소는 바뀔 수 있으므로 주기적인 링크 점검이 필요하다.
- **필드 상태** 항목별 정보 출처 (사용자 확정, Q8):

| 항목 | 정보 출처 | 바뀌는 정도 | 비고 |
|---|---|---|---|
| 운영·휴장 여부 | 지자체·시설관리공단 공지 | 수시 | 공지 확인 날짜를 함께 표시 |
| 날씨 | 날씨 정보 서비스 (예: 기상청 API) | 실시간 | 구장 좌표로 자동 조회 |
| 잔디 상태 | 1차: 공개 자료 (사용자 확정, Q10) / 2차: 이용자 평가 | 계절·수시 | 1차는 천연·인조 잔디 구분 등 공개 자료에 있는 것만 표시 |
| 코스 난이도 | 1차: 공개 자료 (사용자 확정, Q10) / 2차: 이용자 평가 | 거의 고정 | 1차는 코스 길이, 파(PAR) 등 공개 자료에 있는 것만 표시. 근거 없이 난이도 등급을 매기지 않음 |

- 정보를 얻지 못한 항목은 "정보 없음"으로 표시하고 값을 지어내지 않는다.

**배포 (Q2·Q3 답변에서 따라오는 조건)**
- 여러 이용자가 PC와 스마트폰에서 함께 쓰려면 **인터넷에 공개 배포**해야 한다. 내 PC에서만 실행하면 다른 사람이나 스마트폰에서 접속할 수 없다.
- **무료 호스팅으로 시작한다** (사용자 확정, Q9). 무료 요금제는 접속 속도, 저장 용량, 일정 시간 미사용 시 잠자기 같은 제한이 있을 수 있다. 어떤 서비스를 쓸지는 설계 단계에서 Python 지원 여부와 제한을 비교해 정한다. 이용자가 늘면 유료 전환을 다시 검토한다.
- 무료 주소(서비스가 주는 기본 주소)를 쓰고 도메인은 사지 않는다.
- 스마트폰 지원은 별도 앱이 아니라 **휴대폰 화면에 맞춰지는 웹사이트(반응형 웹)**로 한다 (사용자 확정, Q7). 로그인이나 기기 간 즐겨찾기 동기화는 하지 않는다.

**예약 (1차 방식 A)**
- 이 사이트는 **안내와 링크 연결만** 한다. 예약 자체는 각 지자체 공식 사이트에서 이루어진다.
- 그래서 1차에서는 지자체 협약, 예약자 개인정보 처리, 결제가 필요 없다.
- 다른 사이트에 자동으로 로그인하거나 자동 예약하는 방식(스크래핑, 매크로)은 쓰지 않는다.

**권한·보존**
- 사용자가 승인하기 전에는 코드 작성, 외부 사이트 수집, 배포를 하지 않는다.

## 5. 완료 기준 (1차 범위)

전체 1차 개발이 끝났다고 판단하는 조건이다. (이 문서를 쓴 것만으로는 완료가 아니다.)

- **AC-01 의도 확정**: 사용자가 이 문서의 목표, 범위, 미결 사항 답변을 확인함 / 확인 방법: 사용자 승인 메시지 / 증거: 승인 기록과 문서 버전
- **AC-02 현황 데이터**: 전국 파크골프장 데이터를 출처와 수집일을 붙여 확보함 / 확인 방법: 데이터 파일의 건수, 필수 항목 채움 비율 확인 / 증거: 데이터 파일과 출처 목록
- **AC-03 지도·검색**: 웹페이지에서 지역별 검색과 지도 표시가 동작함 / 확인 방법: 로컬 실행 후 화면 확인 / 증거: 실행 화면 캡처
- **AC-04 상세 정보**: 구장을 선택하면 상세 정보와 예약 방법이 보임 / 확인 방법: 무작위 구장 몇 곳 확인 / 증거: 화면 캡처
- **AC-05 예약 연결**: 각 구장에서 공식 예약 페이지(또는 전화번호)로 이동할 수 있음 / 확인 방법: 전체 링크 자동 점검 / 증거: 링크 점검 결과 (정상·깨짐·없음 개수)
- **AC-06 PC·스마트폰**: PC와 스마트폰 화면 모두에서 사용할 수 있음 / 확인 방법: 두 화면 크기에서 확인 / 증거: 캡처
- **AC-07 전국 범위**: 17개 시·도 모두의 구장이 들어 있음 / 확인 방법: 시·도별 구장 수 집계 / 증거: 집계표
- **AC-08 필수 항목**: 각 구장에 홀 수, 위치 정보, 필드 상태가 표시됨 (모르는 값은 "정보 없음"으로 표시하고 지어내지 않음) / 확인 방법: 항목별 채움 비율 집계 / 증거: 집계표
- **AC-09 필드 상태 날짜**: 필드 상태 4개 항목(운영·휴장, 날씨, 잔디 상태, 코스 난이도)이 각각 출처와 마지막 확인 날짜와 함께 표시됨 / 확인 방법: 화면 확인 / 증거: 캡처
- **AC-11 날씨 자동 표시**: 구장 위치 기준 날씨가 자동으로 표시됨 / 확인 방법: 여러 지역 구장 확인 / 증거: 캡처
- **AC-10 공개 접속**: 배포 주소로 PC와 스마트폰에서 접속됨 / 확인 방법: 실제 기기 접속 / 증거: 접속 화면 캡처

## 6. 범위 외

이번 요청(의도 정리 단계)에서 하지 않는 일:

- 코드 작성, 프로젝트 폴더 구성, 패키지 설치
- 외부 사이트 데이터 수집(크롤링)
- 서버 배포, 도메인 구입

1차 개발에서도 하지 않는 일:

- 이용자 평가·제보 기능 — 2차로 미룸 (사이트 인지도가 늘면 추가)
- 빈 시간대 조회 (B), 사이트 안 예약 (C) — 장기 목표로 보류
- 지자체 예약 사이트에 사용자 대신 자동 로그인하거나 자동 예약하는 기능
- 회원 가입, 개인정보 수집, 결제
